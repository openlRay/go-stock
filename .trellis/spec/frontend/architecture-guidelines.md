# 前端架构规范

## 适用范围

新增或修改路由、路由页面、业务组件和跨业务公共组件时使用本规范。目标是让加载边界、页面编排、业务逻辑与基础 UI 的依赖方向稳定可检查。

## 目录职责

| 目录 | 全局职责 | 禁止内容 |
| --- | --- | --- |
| `src/router/` | URL、路由名称、重定向、元信息和动态加载边界 | 页面实现、业务状态、同步导入全部路由页面 |
| `src/views/` | 路由级数据加载、页面布局与业务模块编排 | 可跨页面复用的基础 UI、与页面无关的业务能力 |
| `src/components/common/` | 跨业务复用的基础 UI 和稳定交互骨架 | 业务 API、业务 store、领域字段和仅服务单一页面的样式分支 |
| 业务组件目录 | 领域状态、领域交互和可在同一业务内复用的区块 | URL 配置、应用级基础 UI 的重复实现 |

依赖方向应保持为“路由页面 → 业务组件 → 公共组件”。公共组件不得反向导入页面或业务模块。

## 路由加载契约

所有路由页面必须使用 Vue Router 原生的 `dynamic import()`，以路由为边界交给 Vite 拆包。不要先同步导入页面，也不要在路由记录外额外套 `defineAsyncComponent`。

```js
// 正确：路由访问时才加载页面模块。
{
  path: '/example',
  name: 'example',
  component: () => import('../views/ExampleView.vue')
}
```

```js
// 错误：同步导入会把页面加入首屏依赖图。
import ExampleView from '../views/ExampleView.vue'

{
  path: '/example',
  component: ExampleView
}
```

路由配置只描述导航，不拥有请求、表单状态或领域逻辑。

## 页面与组件边界

- View 是路由入口和编排层，可以组合多个业务组件，但不应被当作公共组件复用。
- 业务组件拥有领域交互；只有确实跨业务稳定复用的能力才能进入公共组件目录。
- 公共组件通过 props、slots 和 events 表达契约，不读取调用方私有状态，也不直接调用业务 service。
- 不为目录整齐创建只转发 props 的空壳 View；历史页面只在发生实质性重构时迁移，避免无业务收益的大范围 import 变化。
- 新增公共能力前先确认是否已有可复用实现，禁止复制弹框、表单布局等应用级骨架。

## 公共组件准入

公共组件至少满足以下条件之一：

- 已存在多个真实的跨业务调用方；
- 属于已经确认的应用级稳定交互骨架；
- 其输入、输出和副作用边界能够脱离具体业务完整描述。

仅使用一次、携带领域文案或依赖业务 API 的实现，应留在业务目录。不要为了“以后可能复用”提前抽象。

## 验证要求

- 修改路由导入边界时运行前端 build，确认 import 可解析且生成独立 chunk。
- 目录迁移时检查所有相对 import、路由名称和导航行为。
- 公共组件修改根据真实风险检查键盘焦点、受控状态、滚动和响应式行为。
- 纯目录说明或不改变行为的文案修改不要求自动化测试。
