# 前端质量规范

## 代码注释契约

非显然的实现约束必须有注释。注释应解释“为什么这样做”、职责边界或防止的故障，不能只把下一行代码翻译一遍。

代码注释统一使用中文。遇到以下逻辑时必须补充详细注释：

- 日历、Cron、时区、单位或跨层数据转换语义；
- 容易被误删的第三方库约束，例如 Modal 必须保留真实 DOM 根节点才能正确 focus trap；
- latest-request-wins、取消、teardown 或过期异步响应处理；
- 为兼容历史数据而保留的回退行为；
- 公共组件与业务调用方之间的状态和副作用归属；
- 表面上多余、实际承担安全或兼容职责的分支。

```js
// 错误：只重复代码动作，没有留下约束知识。
// 更新结果。
state.value = result

// 正确：解释未来修改必须保留的竞态约束。
// 只允许最新请求覆盖页面状态，避免较慢的旧响应回写过期结果。
if (requestId === latestRequestId) state.value = result
```

明显的赋值、模板文案和标准 Vue 语法不需要注释。较长的可复用契约应在代码旁保留摘要，并把完整规则写入对应 spec，避免实现文件被大段说明淹没。

## 按风险选择验证范围

自动化测试不是每次改动的固定流程。必须选择能够发现当前 diff 真实回归风险的最小证据集。

| 修改类型 | 默认验证方式 |
| --- | --- |
| 文案、注释、spec、局部 CSS token、不改变行为的重命名 | diff review 与 `git diff --check`；默认不跑自动化测试 |
| 无新增分支的局部模板或 prop 接线 | 静态检查；必要时做一次本地人工核对 |
| 纯业务规则或数据转换 | 覆盖新增分支和非法边界的定点单元测试 |
| 路由导入边界、公共组件契约、其他编译敏感修改 | 前端 build 加最小定点检查 |
| 已出现可见交互故障的 bug 修复 | 静态检查无法证明时，做定点回归或复用本地外部浏览器复现 |
| 跨层契约、影响面广的依赖调整、发布门禁 | 运行相关 package 测试/build；只有影响面确实覆盖全仓时才跑全量测试 |

小改动跳过自动化测试是正确选择。最终报告必须说明实际检查范围，不能把定点验证描述成全量验收。

## 浏览器验收契约

确需浏览器验收时，连接并复用用户电脑上已经打开的本地外部浏览器、现有标签页和登录态。禁止使用 Codex in-app Browser 和独立的 `playwright-cli`。

如果本地外部浏览器未连接，应明确报告浏览器验收被阻塞，不得静默切换浏览器表面。纯文档、纯注释以及静态证据足以覆盖的小改动不需要浏览器自动化。
