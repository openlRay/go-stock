# 表单弹框规范

## 适用范围

新增或修改承载表单、设置项或多步骤业务内容的弹框时使用本规范。简单的确认和提示可以继续使用 UI 框架提供的轻量 preset，不要求统一成大型表单弹框。

## 职责边界

应用级弹框骨架只负责所有业务都需要的稳定行为：

- 受控显隐及关闭事件；
- 标题、关闭入口、可滚动正文和底部操作区；
- viewport 约束、响应式尺寸和基础视觉层级；
- dialog 语义、无障碍名称与键盘焦点。

业务调用方负责字段、校验、请求、loading、提交/取消语义和按钮文案。基础骨架不得根据业务类型增加分支，也不得导入业务 service 或 store。

## 结构契约

- 标题与底部操作区保持可见，长正文只在内容区内部滚动。
- flex 滚动容器必须设置 `min-height: 0`，避免正文撑破 viewport。
- 使用 Naive UI `n-modal` 时，其直属内容节点必须是单个真实 DOM 元素；不要使用 Fragment 或无法透传 DOM 的中间层，否则 focus trap 可能失效并导致输入控件无法编辑。
- 父弹框使用显式 `z-index` 时，后打开的子弹框必须显式使用更高层级；不得依赖 teleport DOM 顺序或组件默认值。通用弹框骨架可以暴露可选层级参数，具体父子关系由业务调用方声明。
- 提升 teleport 下拉浮层时，选择器必须命中真实 follower 容器，例如 `body > .v-binder-follower-container:has(.n-select-menu)`；禁止使用 `body > div:has(.n-select-menu)`，后者会把包含下拉菜单的整个弹框祖先一并抬升。
- 表单弹框默认禁止点击遮罩关闭，避免误操作丢失未提交内容；若业务允许遮罩关闭，必须明确处理未保存状态。
- footer 不存在时不保留空白操作区。

## 统一视觉规则

应用内表单弹框使用以下视觉语言，具体业务内容不得复制或覆盖外层骨架：

| 区域 | 全局规则 |
| --- | --- |
| 容器 | `#fff` 背景、`1px #dde4ec` 边框、`18px` 圆角、`0 24px 70px rgb(15 23 42 / 22%)` 阴影。 |
| 宽度 | 桌面端使用业务所需宽度，但最终取 `min(业务宽度, 100vw - 32px)`。 |
| 高度 | 最大高度取 `min(920px, 100vh - 32px)`；正文独立滚动。 |
| 标题栏 | 最小高度 `68px`、水平 padding `24px`、底边框 `#e2e7ee`；标题 `18px`、字重 `700`。 |
| 关闭入口 | `34px` 正方形、`9px` 圆角、中性灰文字；hover 背景 `#f3f5f7`。 |
| 正文 | 水平 padding `24px`，正文色 `#202733`、字号 `14px`、左对齐。 |
| Footer | 最小高度 `72px`、水平 padding `24px`、操作间距 `10px`、顶边框 `#e2e7ee`；次要操作在前，主操作在后。 |
| 窄屏 | `<= 640px` 时两侧各保留 `10px`，圆角降为 `14px`，标题、正文和 footer 水平 padding 降为 `16px`。 |
| 反馈色 | 绿色用于成功或主要确认，蓝色用于信息摘要，红色只用于错误和破坏性动作。 |

业务面板可以使用自己的强调色和布局，但不得改变弹框圆角、阴影、标题栏、滚动区和 footer 的应用级一致性。

## 交互与无障碍

- 弹框必须有可感知标题和对应的 accessible name。
- 关闭入口必须是语义化 button，提供明确的 `aria-label`。
- 打开后焦点进入弹框；关闭后焦点返回触发元素。
- 文本、数字、下拉、日期/时间、checkbox 等控件必须可通过键盘操作。
- 主操作在提交中应防止重复触发；校验失败时保持弹框打开并展示与字段相关的错误。
- 不能用禁用样式代替错误说明，也不能依赖颜色作为唯一状态提示。

## 错误与正确模式

错误模式：

- 每个业务弹框复制标题栏、关闭按钮、滚动和 footer CSS；
- 把领域字段或业务 API 做成通用弹框骨架的配置分支；
- Modal 内容根节点为 Fragment，导致 focus trap 无法建立；
- 整个弹框随正文滚动，使标题和确认按钮离开 viewport。

正确模式：

- 公共层只提供稳定窗口骨架，业务层组合自己的内容与操作；
- 新增业务需求优先通过内容组合解决，只有多个真实调用方共享的稳定行为才扩展公共契约；
- 视觉 token 在公共层统一维护，业务组件不复制外框样式。

## 验证要求

- 纯 token 或文案调整默认进行 diff review 和必要的人工核对。
- 修改显隐、焦点、滚动、表单输入或 footer 状态时，执行能够覆盖该风险的最小定点验证。
- 修改嵌套弹框层级时，至少验证子弹框的遮罩和内容均位于父弹框之上，并验证关闭子弹框后父弹框仍保持可用。
- 需要浏览器验收时复用电脑上已连接的本地外部浏览器，不使用 Codex in-app Browser 或独立 `playwright-cli`。
- 验收至少覆盖打开/关闭、键盘焦点、输入编辑、长正文滚动、主次操作状态和窄屏尺寸。
