# AI 交互式生成选股条件

## Goal

在策略编辑弹框中增加轻量、可迭代的 AI 助手，让用户通过自然语言生成和调整选股条件，并且只有在用户明确应用建议后才更新表单草稿。

## Background

- 当前“我的策略”只持久化名称、自然语言 `Query`、描述和排序；它不是本地策略 DSL，也不保存 AI 对话。
- 手动选股和策略定时选股都在执行时读取最新 `Query`，再调用现有东方财富自然语言选股接口，因此本功能继续产出兼容的自然语言条件文本。
- 页面已有东方财富返回的 `traceInfo.showText`，可用于执行后确认上游实际理解的条件；首版不在本地重建选股解析器。
- 项目已有 AI 填充表单、AI 草稿润色、latest-wins 和可取消生成等模式，可复用其配置解析、安全错误和生命周期约束。
- AI 模型配置由现有统一 resolver 管理；前端不维护第二套 provider 或默认模型规则。

## Requirements

### R1 入口与布局

- 保留策略名称、选股条件、策略描述和最终保存流程。
- 在“选股条件”区域提供“AI 帮我生成”入口；默认不展开，避免影响纯手工用户。
- 展开后采用弹框内的轻量助手，而不是独立全屏聊天窗口。
- 助手应展示用途说明、对话模型选择、调整指令输入、常用示例和建议稿区域。
- 没有可用对话模型时给出设置引导，但手工编辑和保存仍完整可用。

### R2 轻量迭代交互

- 第一次请求以当前“选股条件”和用户指令为上下文；当前条件为空时允许从零生成。
- AI 返回独立建议稿，不得自动改写正式“选股条件”字段，不得自动保存或执行选股。
- 用户可以直接编辑建议稿，并基于当前建议继续输入“排除创业板”“增加换手率限制”等调整指令。
- 每次继续调整只保留最新建议稿作为下一轮上下文；首版不展示或持久化完整聊天历史。
- 用户必须点击“应用到选股条件”后，建议稿才写入表单草稿；写入后仍需点击原有“保存”才持久化策略。
- 用户可以放弃建议并回到原有手工内容。

### R3 请求生命周期与错误保护

- 同一助手只允许一条活动请求；新请求、关闭策略弹框、切换编辑对象或组件卸载时取消或作废旧请求。
- 过期请求不得覆盖较新的建议稿或表单内容。
- AI 调用失败、取消、返回空内容、格式非法或内容超限时保持正式选股条件及上一份可用建议不变。
- 后端统一解析模型配置，使用请求级配置副本关闭 reasoning，并将模型输出作为不可信输入校验。
- RPC 和日志不得暴露 API Key、完整模型响应、完整 prompt、provider body 或底层敏感错误。

### R4 兼容性

- `CustomStrategy` 数据表和现有 `SaveCustomStrategy` 契约保持不变，AI 对话和建议不入库。
- 现有热门策略、我的策略、手工搜索、策略保存/编辑/删除和策略定时选股行为保持不变。
- AI 生成结果仍是自然语言 `Query`，不新增本地条件执行器。

## Acceptance Criteria

- [x] AC1：用户可在新增或编辑策略弹框中展开 AI 助手；不展开时原表单行为不变。
- [x] AC2：用户可选择可用对话模型，输入目标或调整指令并获得独立建议稿。
- [x] AC3：AI 返回或继续调整建议时，正式“选股条件”字段保持不变。
- [x] AC4：用户可编辑建议稿、继续调整、放弃建议；只有点击“应用到选股条件”才更新表单草稿。
- [x] AC5：应用建议不会自动保存；点击原有“保存”后才通过现有策略接口持久化。
- [x] AC6：关闭弹框、切换策略、取消请求、AI 失败、空结果、非法格式和过长结果均不会破坏原表单或上一份成功建议。
- [x] AC7：未配置可用对话模型时显示可操作提示，手工编辑和保存仍可使用。
- [x] AC8：后端定点测试覆盖配置解析、输出校验、取消/latest-wins 和零持久化；前端构建通过。

## Out of Scope

- 本地结构化条件 DSL、可视化条件构建器或本地自然语言解析器。
- AI 对话跨弹框、跨页面或跨应用重启持久化。
- 回测、收益评价、买卖点、仓位、止损或直接交易。
- AI 自动保存策略、自动执行选股或自动采用东方财富 `traceInfo`。
- 完整聊天消息流、流式 token 展示、长期记忆和多会话管理。

## Technical Notes

- 生成时的最新建议稿只是内存状态；保存后的唯一权威值仍是 `CustomStrategy.Query`。
- 东方财富对条件的真实解析仍以运行选股后的 `traceInfo.showText` 为准。
- 本任务没有阻塞性开放问题。
