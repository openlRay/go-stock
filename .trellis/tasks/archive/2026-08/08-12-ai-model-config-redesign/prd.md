# 重构 AI 模型配置管理

## Goal

将 AI 模型配置页从“本地暂存后全量保存”改为可即时生效、操作结果明确的配置管理页，并按不同模型供应商的实际能力开放常用生成参数，减少误配和不兼容请求。

## Background and Confirmed Facts

- 当前新增、编辑、复制、删除只修改 `ai-config-manager.vue` 中的临时数组，必须再次点击页面顶部“保存配置”才会写入数据库。
- 当前后端 `UpdateAiConfigs` 接收完整数组并执行全量同步；它会删除未包含在数组中的旧记录，不适合作为单条即时 CRUD 接口。
- AI 配置通过 SQLite `ai_config` 表持久化，并由 `GetSettingConfig()` 重新加载到运行时配置，因此单条写入成功后需要刷新运行时缓存。
- 当前配置字段只有名称、接口地址、API Key、模型名称、Temperature、MaxTokens、Timeout、深度思考和 HTTP 代理。
- 请求层包含 OpenAI 兼容、DeepSeek、Qwen、Ark、OpenRouter、Claude、Ollama、Gemini 等适配器；各适配器支持的参数集合和取值范围不同。
- 当前普通对话请求只透传 `temperature`、`max_tokens` 和 `thinking`；Agent 请求也只映射现有少量字段。
- OpenAI 兼容 SDK 已具备 `max_completion_tokens`、`top_p`、`stop`、`presence_penalty`、`frequency_penalty`、`seed`、`response_format` 等能力；部分供应商另有 `top_k`、推理预算/强度等专属能力。
- 现有 AI 助手、诊股、飞书机器人、定时任务等均通过同一个 `AIConfig` 使用模型，因此新增字段必须在所有请求路径中保持一致语义。
- `trellis mem` 未找到此前关于本次参数范围或高级参数 UX 的已记录决策。

## Requirements

### R1. 即时新增与编辑

- 移除页面顶部“保存配置”按钮及“修改后请保存”的提示。
- 新增或编辑抽屉中的主按钮改为明确的“保存”。
- 用户点击保存后立即调用单条新增/更新接口。
- 只有后端写入成功才关闭抽屉并刷新列表；失败时保留表单内容并显示可理解的错误。
- 防止重复提交，并对必填项和参数范围进行前后端校验。

### R2. 即时复制与删除

- 点击“复制”后先显示二次确认，明确源配置名称，并说明确认后将立即创建副本。
- 确认复制后由后端直接创建副本；后端清空副本 ID、生成不冲突的副本名称，并返回新配置供列表刷新。
- 点击“删除”后显示二次确认，明确配置名称和删除不可撤销。
- 确认删除后直接调用后端删除接口；失败时保留列表项并显示错误。
- 删除前在同一事务中检查引用；若飞书机器人设置或定时任务仍引用该配置，则阻止删除并返回结构化引用列表。
- 删除受阻时，前端列出引用类型和可识别的来源名称/任务名称，不自动清理、替换或重写引用。
- 新增、编辑、复制、删除成功后刷新运行时配置缓存，并通知其他依赖配置的页面更新。

### R3. 模型能力驱动的配置表单

- 表单区分基础连接信息、生成参数、推理参数和网络设置，避免所有选项平铺。
- 每个非显而易见的配置项都提供小问号提示，包括 Temperature、Token 限制、Timeout、采样、重复惩罚、停止序列、输出格式、推理选项和代理设置。
- 参数控件显示适用范围、推荐用法和兼容性提示，例如 Temperature 与 Top P 通常不建议同时调整。
- 根据接口平台和模型名称推导能力档案，只展示或启用该能力档案支持的参数。
- 接口地址控件既提供常用平台预设，也必须允许直接输入或粘贴任意合法 HTTP(S) 兼容接口地址。
- 自定义/无法识别的 OpenAI 兼容接口至少提供安全的通用参数集合，不能假定其支持供应商专属字段。
- 已保存但当前能力档案不支持的旧参数不得静默丢失；界面应给出兼容性提示，发送请求时不得盲目透传。
- 高级参数仅通过项目定义的结构化字段开放；不提供任意请求 JSON 输入，也不允许用户覆盖 `model`、`messages`、`tools` 等系统管理字段。

### R3.1 推理能力配置

- 将现有单一“深度思考”布尔开关升级为结构化推理配置。
- 推理模式至少包含关闭、自动和开启；仅支持开关的供应商使用该模式控件。
- 对支持档位的模型提供“推理强度”，能力档案按供应商暴露其真实支持值：
  - OpenAI 兼容基线：低、中、高；若具体平台或模型支持更细档位，可扩展最小/极高等选项。
  - OpenRouter：无、最小、低、中、高。
  - Ark：最小、低、中、高。
  - Gemini：最小、低、中、高。
- 对支持 Token 预算的模型提供“推理预算”：
  - Claude 映射为 `budget_tokens`，并允许使用供应商支持的自适应模式。
  - Gemini 映射为 `thinkingBudget`，与 `thinkingLevel` 根据能力约束互斥或组合。
  - OpenRouter 映射为 reasoning `max_tokens`。
- 仅支持推理开关、不支持档位或预算的模型，不展示无效控件；例如当前 DeepSeek 与 Qwen 适配器默认只稳定映射启用/关闭。
- 推理强度和推理预算必须具有问号提示，说明更高配置通常增加延迟、Token 消耗和成本，但可能提高复杂任务质量。
- 当模型能力变化导致已有推理配置不再支持时，保存前提示用户，并由后端按安全策略规范化，不能静默发送无效字段。
- AI 助手底部现有“思考模式”开关只控制当前会话是否启用推理：关闭时临时禁用；开启时沿用所选模型配置中的推理强度和推理预算；该开关不修改或回写已保存配置。

### R4. 参数持久化与请求映射

- 扩展 `AIConfig` 数据契约与数据库迁移，旧配置升级后继续可用并获得安全默认值。
- 后端集中负责参数规范化、范围校验、能力判断和供应商映射，前端不单独维护另一套不一致的规则。
- 直接聊天、带工具聊天和 Agent 模式共享同一份有效参数解析结果。
- 不支持或互斥的参数必须被拒绝、归一化或明确忽略并给出可诊断信息，不能造成隐蔽请求失败。
- API Key 不得出现在日志或错误消息中。

### R5. 兼容现有入口

- AI 助手、AI 诊股、飞书机器人、定时任务和设置导入仍能读取既有配置。
- 保留现有全量 `UpdateAiConfigs` 兼容入口供设置导入使用，但配置管理页改用单条 CRUD 接口。
- 生成的 Wails 前端绑定与 Go 接口保持同步。

## Acceptance Criteria

- [ ] 页面顶部只保留“添加 AI 配置”，不再出现全局“保存配置”。
- [ ] 新增和编辑点击保存即写入数据库；刷新页面后数据仍存在，失败时抽屉不关闭。
- [ ] 复制和删除均有二次确认，确认后立即执行；取消确认不会改变任何数据。
- [ ] 被飞书机器人或定时任务引用的配置无法删除，错误提示会列出全部已识别引用；解除引用后可正常删除。
- [ ] 任一 CRUD 成功后，列表和 AI 助手模型下拉无需重启应用即可获得最新配置。
- [ ] 至少覆盖通用生成参数以及已接入供应商能够稳定映射的专属参数；推理模式、推理强度和推理预算按模型能力展示，不支持项在 UI 和请求层行为一致。
- [ ] 所有高级参数都有用途、范围和兼容性提示，非法值无法保存。
- [ ] 接口地址既可从预设中选择，也可直接输入自定义 HTTP(S) 地址。
- [ ] 旧版 AI 配置经过自动迁移后仍可用于直接聊天和 Agent 调用。
- [ ] 新字段能完成“表单 → Wails → Go → SQLite → 运行时模型配置 → 实际请求”的往返，不丢失值。
- [ ] 单条 CRUD、能力解析、校验和主要供应商映射具有自动化测试；前端构建、Go 测试和项目构建通过。

## Out of Scope

- 不在本任务中新增模型供应商或替换现有 Eino 模型 SDK。
- 不修改 AI 助手的对话布局、提示词管理或 Agent 模式选择。
- 不承诺通过 `/models` 接口自动获得所有厂商的完整能力元数据；缺失元数据时使用项目维护的能力档案和安全回退。
- 不在本任务中建设独立的在线模型能力注册中心。
- 不自动清理或替换飞书机器人、定时任务中的 AI 配置引用。
