# 重设计定时任务执行时间设置

## Goal

让普通用户无需理解 Cron 语法即可设置定时任务，同时保留专家直接编辑 Cron 的能力，并提供可选的 AI 自然语言辅助填充。

## Background

- 当前配置器直接暴露“秒、分、时、日、月、周”以及范围、循环、指定等底层概念，认知负担较高。
- 当前 UI 能生成小于 60 秒的规则，但任务提交时又禁止该规则，交互前后不一致。
- 用户已经确认新的交互方向：手动设置是主流程，AI 只是辅助填充，专家模式保留直接编辑能力。
- 北京和上海当前均使用中国标准时间 UTC+8，产品统一使用 IANA 时区 `Asia/Shanghai`，界面显示“中国标准时间（北京/上海，UTC+8）”。

## Requirements

- 默认展示直观的手动设置，支持四种常用模式：间隔执行、每天、每周、每月。
- 切换模式时，下方字段、中文摘要、Cron 表达式和未来执行时间必须完整联动；每个模式保留本次弹窗内上次填写的值。
- 普通模式不展示秒、范围、循环、不指定等 Cron 专业术语，秒固定为 0。
- 间隔执行支持分钟、小时和天：分钟 `1..59`，小时 `1..23`，天 `1..31`。
- “每 N 天”生成 `0 0 0 */N * *`，在 `00:00` 按月内日期步进；跨月会按新月份重新计算，不承诺严格间隔 `N×24` 小时。
- AI 输入位于手动表单上方，是可选的“识别并填充”能力，不是唯一入口或独立保存入口。
- AI 只解析执行时间并返回结构化意图，不得修改任务类型、任务参数、启用状态等字段，也不得直接保存任务。
- AI 解析结果必须经过后端结构校验和 Cron 校验；识别失败或结果含糊时保留原表单内容并给出安全错误。
- 没有 AI 配置或模型调用失败时，手动设置与专家 Cron 仍可正常使用。
- 专家设置使用单个 Cron 文本框，提供六段字段说明、常用符号说明、示例、实时语法校验、中文摘要和未来执行时间。
- 可映射到常用模式的专家表达式应自动回填手动表单；合法但无法映射的表达式允许作为“自定义 Cron”保留。
- 编辑既有任务时，常见表达式自动进入对应手动模式；复杂表达式进入自定义 Cron 状态且不得被静默改写。
- 现有定时任务数据结构和六段式 `robfig/cron` 调度保持兼容，不迁移数据库。
- 弹窗视觉必须与已确认设计稿保持一致：大圆角容器、独立标题栏和底部操作栏、绿色 AI 区、四等分模式切换、蓝色摘要预览区、克制的专家折叠区，以及设计稿对应的边框、圆角、间距和按钮层级。
- 将已确认弹窗的稳定骨架抽为通用组件；Cron 专属面板和业务交互继续由 Cron 编辑器拥有。
- AI 模型服务配置支持且仅支持一个全局默认模型。未显式指定 AI 配置的功能自动使用默认模型，不要求每个业务入口重复选择。
- 定时设置的 AI 辅助区不再展示模型选择器；没有默认模型时给出前往模型服务配置设置默认模型的提示，手动设置与专家 Cron 不受影响。

## Acceptance Criteria

- [ ] 切换四种模式时只显示该模式相关字段，不残留其他模式控件。
- [ ] “每天 12:00”生成 `0 0 12 * * *`；“每 5 分钟”生成 `0 */5 * * * *`；“每 3 天”生成 `0 0 0 */3 * *`；工作日 15:00 生成 `0 0 15 * * 1,2,3,4,5`。
- [ ] 用户输入“每天12点整”并识别后，系统使用全局默认模型，表单切换到“每天”、时间填为 12:00，用户仍需点击确认才应用设置。
- [ ] AI 输出缺字段、越界、未知模式或不合法 Cron 时返回用户可理解的错误，且不覆盖当前表单。
- [ ] 专家区清晰说明 `秒 分 时 日 月 周`、`*`、`,`、`-`、`/`，并提供至少三个常用示例。
- [ ] 专家表达式语法错误时不可应用；合法自定义表达式可保留并展示未来执行时间。
- [ ] 时区界面只提供并解释“中国标准时间（北京/上海，UTC+8）”，底层值为 `Asia/Shanghai`。
- [ ] 现有 AI 配置变更监听逻辑保留，AI 配置删除后选择器回退安全。
- [ ] 后端单元测试覆盖结构化意图校验与 Cron 生成，前端生产构建通过，相关 Go 测试通过。
- [ ] 模型服务列表可以将任一配置设为默认，并清晰标识当前默认；首次创建配置时自动建立安全默认，切换默认后其他未指定模型的调用立即生效。
- [ ] 定时设置弹窗与确认设计稿在圆角、边框、间距、色彩、信息层级和操作区布局上保持一致。
- [ ] 通用弹框组件拥有标题、关闭按钮、可滚动正文、底部操作栏、响应式尺寸和基础视觉；业务组件不复制这些骨架样式。

## Out of Scope

- 不支持秒级调度。
- 不在本次实现中扩展数据库以保存独立时区或结构化调度对象。
- 不将交易日上午/下午分段、节假日交易日历等复杂业务规则建模为多个 Cron；这类规则继续由任务执行逻辑控制或使用自定义 Cron。
