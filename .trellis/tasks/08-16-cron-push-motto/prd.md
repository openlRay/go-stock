# 定时任务推送与我的格言

## Goal

让用户能够维护自己的格言库，并通过现有 AI 模型润色格言；同时增强定时任务，使任务可在执行完成后推送结果，并支持按计划随机推送最多三条格言。

## Background

- 当前定时任务由 `backend/models.CronTask` 持久化，`backend/agent.CronTaskApi` 负责 CRUD、调度执行和运行结果记录，前端入口为 `frontend/src/components/cron-task-manager.vue`。
- 当前任务只记录 `LastRunResult`，没有逐任务的“执行完成后推送”字段。
- 项目已有本地通知、Web 浏览器通知、前端 `newsPush`、飞书和钉钉推送能力；各渠道是否真正发送由全局通知设置控制。
- 当前主导航在 `frontend/src/App.vue` 中定义，“关于”是一个顶级入口；路由统一使用动态导入。
- 项目已有 SQLite/GORM additive migration 和统一 AI 配置解析/模型创建能力，可复用于格言持久化与 AI 润色。

## Requirements

### R1 定时任务执行结果推送

- `CronTask` 增加一个默认关闭的“执行完成后推送”布尔字段。
- 创建、编辑和查询定时任务时完整保存并回显该字段。
- 开关打开时，任务执行结束后发送一次结果通知；开关关闭时保持现有行为。
- 推送必须在任务业务执行结束、运行结果确定后发生，且通知发送失败不得篡改任务本身的成功/失败结果。
- 定时调度和“立即执行”必须走同一执行与推送规则。
- 开关打开后，成功和失败都推送一次最终结果，发送到全局设置中已启用的全部渠道（本地/Web、飞书、钉钉）。

### R2 “我的”顶级入口与格言管理

- 在“关于”之后新增顶级“我的”入口，进入独立路由页面。
- “我的”页面采用可扩展的功能 Tab 结构，首个 Tab 为“格言”。
- 格言包含正文和创建/更新时间。
- 用户可以新增、查看、编辑和删除格言；空正文不得保存，删除需要确认。
- 列表具备稳定排序和空状态，保存后无需刷新整个应用即可看到最新数据。

### R3 AI 润色

- 格言编辑界面提供 AI 润色入口，并允许选择现有 AI 配置。
- AI 润色只处理当前格言正文，不允许模型扩大为其他工具或数据源调用。
- AI 返回内容先进入可编辑草稿，不自动保存；用户确认保存后才覆盖持久化内容。
- 缺少可用 AI 配置、空正文、模型失败或返回空内容时提供安全且可理解的错误提示，保留用户原文。

### R4 定时推送格言

- 定时任务类型新增“推送格言”。
- 选择该任务类型时自动启用并锁定“执行完成后推送”，保证任务类型语义不会被关闭；其他任务类型仍由用户自由切换该开关。
- 执行时从格言库随机选择最多三条格言并合并为一次通知，同一次执行不得重复。
- 格言不足三条时推送现有全部格言；格言为空时任务失败并记录明确、用户安全的结果。
- 该任务复用通用的任务完成推送机制，不建立第二套通知实现。

### R5 定时任务管理回归修复

- 任务类型和任务状态筛选未选择时必须明确显示“全部”，并以空条件查询全部数据。
- 用户点击“执行”后，前端不能只刷新启动状态；任务真正执行完成并写回最近执行时间、运行次数和结果后，必须自动刷新当前列表。
- 调度触发和立即执行使用同一完成事件，页面只监听自己的订阅并在卸载时注销。
- “执行完成后推送”开关及其说明在表单中保持左对齐、占满字段内容区，不得挤压或覆盖左侧标签。

### R6 AI 模型服务可用性测试

- “AI 模型服务配置”列表的每条配置都提供“测试”入口。
- 新增或编辑抽屉提供“测试当前配置”入口，可测试尚未保存的当前草稿，不要求先落库。
- 对话模型必须发起一次最小真实生成请求；向量模型必须发起一次最小 embeddings 请求，不能用“获取模型列表”代替可用性测试。
- 测试结果返回成功/失败、耗时和安全的简短结果说明；不得向前端或日志暴露 API Key、完整 prompt、reasoning 或完整上游错误正文。
- 测试请求遵循当前配置的 Base URL、API Key、自定义 Header、代理和超时配置；日常自动化测试使用本地 fake/HTTP server，不访问真实付费模型。

### R7 Docker 动态路由资源完整性

- Docker/Web 二进制必须完整嵌入 Vite 构建产物，包括文件名以 `_` 或 `.` 开头的辅助 chunk。
- 动态路由加载的页面 chunk 及其二级依赖必须由 `/assets/*` 返回正确静态资源；缺失资源返回 `404`，不得回退到 `index.html`。
- 入口 HTML 禁止持久缓存，带内容哈希的静态资源允许长期 immutable 缓存，避免部署后新旧版本混用。

## Acceptance Criteria

- [ ] AC1：新建或编辑任务时可切换“执行完成后推送”，保存后刷新列表/再次编辑仍保持一致；旧任务迁移后默认关闭。
- [ ] AC2：开关关闭的任务执行后不新增通知；开关打开的任务无论由调度器还是“立即执行”触发，都只推送一次最终结果。
- [ ] AC3：通知失败不会把原本成功的业务任务改成失败，也不会阻止运行次数和最近运行结果更新。
- [ ] AC4：“关于”之后显示“我的”顶级入口，进入后默认展示“格言”Tab，路由按需加载。
- [ ] AC5：格言可以完成新增、列表查看、编辑和删除；空正文被拒绝，删除有确认，数据重启后仍存在。
- [ ] AC6：AI 润色可选择现有 AI 配置，成功时只更新编辑草稿；失败或取消时原文不丢失且不会产生数据库写入。
- [ ] AC7：“推送格言”任务可创建、编辑、调度和立即执行；格言充足时一次随机推送三条且不重复，不足三条时推送全部，无格言时记录明确失败原因。
- [ ] AC8：Desktop 与 Web RPC/binding 均可用；相关 Go 定点测试、Web tag 测试和前端 build 通过。
- [ ] AC9：任务类型和状态筛选初始及清空后分别显示“全部任务类型”“全部状态”，查询参数为空且列表展示全部任务。
- [ ] AC10：立即执行返回“任务执行中”后不进行过早刷新；收到完成事件后自动刷新列表，最近执行时间、运行次数和结果与数据库一致。
- [ ] AC11：“执行完成后推送”开关和强制推送说明在创建、编辑以及窄宽度下都位于字段内容区内，标签与说明无重叠。
- [ ] AC12：AI 配置列表和编辑抽屉均可测试；对话/向量配置分别命中真实生成/embeddings 路径，成功展示耗时，失败展示安全错误，草稿测试不产生配置写入。
- [ ] AC13：Linux Web 构建的嵌入 FS 包含 `_commonjsHelpers-*`；缺失 `/assets/*` 返回 404，动态路由相关 chunk 不再收到 HTML fallback。

## Out of Scope

- 不新增新的通知供应商或独立通知账号配置。
- 不做格言公开分享、多人协作、云同步、标签体系、收藏统计或批量导入导出。
- 不让 AI 自动定时创作格言；本期只润色用户已有文本。
- 不改变现有任务最小执行间隔、Cron 编辑器或全局通知设置页面。
- 不做模型质量评分、吞吐压测、Token 计费统计或自动选择最快模型。

## Technical Notes

- 数据库变更采用 additive `AutoMigrate`；不做破坏性迁移。
- 通知边界需兼容 Desktop 系统通知与 Web 事件桥，并复用现有全局渠道开关。
- 格言与 AI 润色业务逻辑进入 backend package，根目录 `App` 方法只承担 RPC 输入边界和 service 编排。
- Cron 完成刷新使用 typed event payload；AI 模型测试复用统一 capability/config/request builder，不建立前端 provider 判断矩阵。
